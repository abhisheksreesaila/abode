# Test-driven development
Work in vertical slices: one failing test,
the simplest code that passes, then refactor.
## Loop
1. Write one failing test for one behavior.
2. Run it and watch it fail for the right reason.
3. Make it pass with the smallest change.
4. Refactor with the tests green.

Round 2 (from your comments)

  • Each drawer has its own close: ⟨ on the sidebar, ✕ on the terminal and the side panel. The three title bar toggles work.
  • The chat reads like a report. Simple shows plan, question and done cards; Detailed adds every tool call.
  • Hover your own message to Edit it, which re-runs from there. Hover any card to "Ask about this".
  • The context meter sits by the mic, and the status bar shows the limit closest to running out (click it for all windows).
  • The Claude picker is tinted orange. Names are now distinct: "Agents" in the sidebar are your threads, "Agent types" are definition files, and "Subagents" is the live tab.

Layout rules

  • Ctrl B sidebar, Ctrl J terminal, Ctrl Alt B side panel. The side panel starts closed.
  • A workspace color shows as a tinted row with a colored left edge, a full-strength guide line on its threads and subagents, a tinted active thread, and the chat chip.
  • Subagents nest under their thread only while running. Clicking one opens the Agents tab.

Customizations

  • Lists the selected workspace's Skills, Agents, MCP servers and Instructions, each marked user-wide or workspace.
  • Clicking a file opens it in the Editor tab. Lock makes it read-only, and markdown renders in the Browser tab.
  • MCP entries show names only and never values.
